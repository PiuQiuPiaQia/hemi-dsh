# Agent Note: 在 SSH exec 通道中传输子进程流

Status: implemented

[English](2026-11-11-ssh-exec-process-streams.md) | 中文

## 问题

[原 SSH 提供方](2026-09-11-posix-ssh-runtime.zh.md)为每条子进程流建立 OpenSSH 转发通道。转发的 Unix 套接字需要双向端点认证，以抵御同一用户替换路径。所选 TLS-PSK 加密套件在独立 Node 中可用，Electron Host 运行时缺少该套件，因此远端文件 RPC 可以成功，命令却在启动前失败。

## 决策

子进程数据与管理 RPC 共用已认证的 SSH exec 通道。helper 在连接内预留流标识，并在启动前确认客户端接入。二进制帧承载程序字节。每条流有独立接收窗口、有界写入和半关闭状态。读端暂停会停止为该流发放额度。写入方每次只向管理帧共用的队列提交一条大小有上限的子进程数据帧。helper 将目标 I/O 接入该协议，并将私有管理描述符与目标的标准输入输出隔离。

## 考虑过的替代方案

**为转发套接字使用 TLS 1.3 双向证书。** 该方案保留 OpenSSH 原生逐通道流控，同时为转发端点引入临时证书签发、固定与交换。

**运行常驻远端 Agent 及服务入口。** 该方案将模型执行、授权及 Session 管理移到远端服务，并引入独立的部署与重连生命周期。SSH 执行提供方由 Host 管理这些职责。

## 影响

客户端和 helper 必须一起部署协议 4。Hemi 管理的目标从当前桌面安装解析新的内容寻址 helper，继续使用保存的服务器和目录。总带宽与断线仍由同一条 SSH 连接决定。回归测试覆盖输出窗口耗尽、心跳与终止请求继续、双工二进制控制与 EOF，以及拒绝接入另一 helper 连接的流。
