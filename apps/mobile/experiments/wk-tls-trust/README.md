# WKWebView self-signed TLS trust experiment

English | [中文](README.zh.md)

One-question experiment with executable evidence: after a `WKWebView` navigation delegate accepts a self-signed leaf for the main frame, do same-origin subresources load, and do they reach `webView(_:didReceive:completionHandler:)`?

## Verdict (this host, macOS WebKit, Xcode 26.6)

- Correct pin (`SHA256(DER)`, anchor-to-leaf, SSL host policy): main frame accepted with one challenge; fetch, redirect fetch, XHR, classic script, ES module, CSS (rule applied), image, woff2 font, and same-origin iframe all loaded with no further challenge — the accepted trust covers same-origin subresources.
- `wss://` to the same host raised its own serverTrust challenge through the same delegate and, once accepted, opened, sent, and echoed.
- Wrong pin (flipped first nibble): every challenge cancelled, navigation failed closed, no request left the client.

The production bridge still carries WebSocket traffic natively (pinned `URLSessionWebSocketTask` with the cookie), so WebKit `wss` behavior is not load-bearing.

## Layout

- `server.py` — local HTTPS server with a generated self-signed leaf, request logging, and one WebSocket echo exchange.
- `main.swift` — minimal AppKit WKWebView client pinning the leaf exactly like the shipped app; logs every challenge and subtest result; exits by itself.
- `run.sh` — generates the certificate and generated assets, serves, runs the client twice (correct pin, wrong pin), writes `results/`.
- `assets/` — subtest page and fixtures; `img.png` and `font.woff2` are generated by `run.sh` and not committed.

## Run

```sh
cd apps/mobile/experiments/wk-tls-trust && ./run.sh
```

Markers in `results/client-*.log`: `CHALLENGE` (delegate consulted), `RESULT` (one subtest), `SUMMARY` (final tally).

## Platform note

This host has no iOS simulator runtime (0 disk images, ~8 GiB free) and the runtime image (~8 GiB) does not fit, so the automated run executes the identical trust code against macOS WebKit. Re-run on a simulator or device when a runtime exists: the same evaluation logic ships in `Sources/HemiMobileCore/TLSPin.swift`. `results/` holds per-run pins and raw logs and is never committed.
